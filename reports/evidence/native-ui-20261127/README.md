Снимки шириной 320, 360 и 1280 пикселей созданы движком Flutter на Linux. Тест открывал настоящий `ClientApp`, разблокировал временный профиль SQLCipher через интерфейс и сохранял отрисованный кадр при масштабе 1 пиксель на логическую единицу. Размер 360 × 800 проверяет мобильную компоновку. Системные панели Android, экран устройства и установка APK в этот прогон не входят. Файлы с префиксом android-api35 получены отдельно через ADB после установки APK.

Для переписки использованы две одноразовые учётные записи с вымышленными именами. Изолированный экземпляр SecureMesh API работал по HTTPS с отдельной базой PostgreSQL и локальным почтовым сервисом Mailpit. Два экземпляра криптографического клиента создали независимые ключи, закрепили ключи друг друга, приняли приглашение и установили сессию OpenMLS через штатный API. Клиенты отправили шесть тестовых реплик, получили подтверждения сервера и синхронизировали историю в двух локальных хранилищах. При захвате широкого экрана клиент загрузил список диалогов и отображаемое имя из этого же API. Учетные данные и личные сообщения существующих пользователей при подготовке снимков не использовались.

Снимки настроек получены в отдельном прогоне с временным локальным профилем. Тест переключил тему и язык и проверил восстановление выбора после повторного запуска интерфейса.

### Переписка на установленном Android

На эмуляторе Android 15 (API 35, x86_64) установлен debug APK с нативным криптографическим ядром. SHA-256 файла APK — `99a241cd4077b16bab2a732332f0b4be4b3d584c9888febd4d0b16042e79a8d0`. Клиент разблокировал свой тестовый профиль SQLCipher по паролю. Пользователь открыл системную клавиатуру и ввёл фразу «See you at the bridge» через ADB в видимое поле. Отдельный Linux-процесс с Dart-клиентом доставки и библиотекой Rust расшифровал её из OpenMLS и отправил «До встречи у моста!». На кадре видны обе фразы. Linux-клиент получил серверный отчёт о получении ответа устройством Android. API вернул восемь конвертов, включая шесть реплик из подготовленной истории.

До исправления при появлении клавиатуры Flutter пересоздавал поле сообщения, и ввод терял фокус. Виджет-тест воспроизвёл замену состояния поля. После исправления три теста переписки прошли и новый установленный APK сохранил введённую фразу полностью. Экран получен штатным `adb exec-out screencap -p`. Для HTTPS использовался сертификат изолированного сервиса, доверенный только тестовым процессом приложения. После проверки профиль, сертификат, переадресация порта и тестовая настройка процесса удалены.

### Просмотр снимка SQLCipher на установленном Android

В Android 15 (API 35, x86_64) приложение открыло системный DocumentsUI. Тест выбрал автономный `.db` из «Загрузок», ввёл пароль, проверил имя аккаунта и открыл обе фразы в истории чата. Тестовый профиль содержал недоступный адрес сервера. После выхода хэш исходного файла остался прежним, приватная копия была удалена, активный профиль в каталоге приложения отсутствовал. SHA-256 проверенного debug APK — `2107faf06852b43fd0590c7b7160ac69cbe89af120ac0247ec9472b38a966ee3`. Тестовые учётные данные и документ удалены после проверки.

### Регистрация v2 на установленном Android

Снимок формы регистрации получен через ADB на эмуляторе Android 15 (API 35, x86_64, 1080 × 2340). Исходники клиента — `f4291f7`, SHA-256 установленного debug APK — `155af72d995aad903aa8b6a1cdc01350ce6e65295a7f9a620f8ecc1d7513e914`. На экране видны отдельные поля для уникального @username и имени, подпись «От 1 до 64 символов» и одно поле пароля. В предыдущем debug APK (`2107faf06852b43fd0590c7b7160ac69cbe89af120ac0247ec9472b38a966ee3`) также проверено отображение и скрытие тестовой строки и включение кнопки регистрации после подтверждения сохранения пароля.

В новой сборке через обычную экранную форму зарегистрирован тестовый аккаунт с отображаемым именем `Z`. Клиент принял код из реального письма Mailpit и открыл «Чаты». Пользователь с тем же @username и паролем затем вошёл через стартовую форму в отдельном локальном профиле. Клиент показал «Устройство ожидает подтверждения». В изолированной базе PostgreSQL имя сохранилось с длиной 1, адрес почты подтверждён, созданы две сессии и два устройства, из которых доверено первое.

Проверка выполнялась через HTTPS с временным CA в процессе тестового APK и ADB-туннелем к локальному серверу. После проверки тестовые профили, сертификат и туннель удалены. У публичного адреса был отдельный результат: при открытии в Chrome на том же эмуляторе `https://securemesh.90-156-230-119.sslip.io/health/live` завершился с `ERR_TIMED_OUT` при действующих настройках сети.

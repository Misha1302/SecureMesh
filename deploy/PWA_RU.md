# Тестовое размещение SecureMesh PWA

GitHub Actions собирает архив `securemesh-pwa` для лабораторного стенда. Сайт проекта на GitHub Pages публикуется отдельно. Для испытания браузерного клиента нужен выделенный HTTPS‑домен, где размещены только файлы PWA. Клиент обращается к одному заданному API по HTTPS. Используйте отдельные тестовые аккаунты и данные.

## Подготовка файлов

Скачайте артефакт задания **Package SecureMesh web app** или соберите его из выбранного коммита в новом каталоге. Для воспроизводимой локальной сборки в Linux установите Rust 1.100.0 и wasm-bindgen CLI 0.2.130.

```sh
rustup toolchain install 1.100.0 --profile minimal --target wasm32-unknown-unknown
cargo +1.100.0 install wasm-bindgen-cli --version 0.2.130 --locked
python3 scripts/package-pwa.py /tmp/securemesh-pwa
cd /tmp/securemesh-pwa
sha256sum --check --strict SHA256SUMS
```

Сборщик берёт файлы по явному списку и заново собирает WebAssembly и JS-загрузчик с закреплённым `Cargo.lock` в чистом каталоге. Эти два файла попадают в пакет после побайтовой сверки с файлами в репозитории. При расхождении сборщик завершает работу с ошибкой. Идентификатор кеша service worker зависит от содержимого пакета. Сборщик встраивает SHA‑256 для каждого кешируемого файла. Service worker проверяет эти хеши при установке и при загрузке отсутствующего в кеше ресурса. Если даже один ресурс не соответствует новой версии, предыдущий кеш остаётся активным. Полностью загруженная версия вступает в работу после закрытия вкладок и окон, которыми управляет предыдущая версия. `SHA256SUMS` позволяет проверить целостность файлов после копирования. Храните ведомость хешей вне корня сайта и публикуйте только проверенный каталог `app/`. Готовьте весь новый каталог перед переключением корня сайта одним действием. Это важно и для первой загрузки, когда service worker ещё не управляет страницей. Исходные файлы из рабочей копии без упаковки подходят для локальной лаборатории.

## Тестовый веб-сервер

Пример для Caddy. Замените `pwa.test.example.org` точным HTTPS‑именем лаборатории и разместите каталог `app/` в `/srv/securemesh-pwa/www/`. Версия PWA в этом репозитории предназначена для API `https://securemesh.90-156-230-119.sslip.io`. Для другого API передайте сборщику `--api-origin https://api.example.org` и укажите этот же адрес в `connect-src`. Сборщик фиксирует адрес в коде, справке и ссылке проверки доступности до расчёта хешей service worker. Адрес участвует в выводе учётных данных и привязке локального профиля. Для существующих аккаунтов переход на другой origin требует отдельной миграции. До её проверки сохраняйте прежний endpoint для существующих профилей.

```caddyfile
pwa.test.example.org {
    root * /srv/securemesh-pwa/www
    header {
        -Server
        Content-Security-Policy "default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob:; manifest-src 'self'; worker-src 'self'; connect-src 'self' https://securemesh.90-156-230-119.sslip.io; base-uri 'none'; object-src 'none'; form-action 'none'; frame-ancestors 'none'"
        X-Content-Type-Options nosniff
        Referrer-Policy no-referrer
        Cross-Origin-Resource-Policy same-origin
        Cache-Control "no-cache, no-transform"
    }
    @entry path / /app
    redir @entry /app/ 308
    @assets path /app/*
    handle @assets {
        @wasm path *.wasm
        header @wasm Content-Type application/wasm
        file_server
    }
    handle {
        respond 404
    }
}
```

CSP разрешает только собственные скрипты и worker, компиляцию WebAssembly и запросы к указанному API. Service worker хранит статические ресурсы из списка для пути `/app/`. Запросы API, заголовки авторизации и пользовательские данные через этот кеш не проходят.

В конфигурации API задайте `BrowserClientOrigin=https://pwa.test.example.org`. Используйте точный адрес лаборатории со схемой и портом при наличии, без пути и завершающей косой черты. Без этой настройки CORS для веб-клиента выключен. TLS‑сертификат API должен быть действителен. До запуска испытаний убедитесь, что инфраструктура API не кеширует ответы с данными аккаунта.

## Установка приложения

На странице `/app/` можно открыть чаты во вкладке. Инструкция по установке доступна отдельно для iPhone и iPad, Android, Windows и Linux. Браузеры, поддерживающие событие `beforeinstallprompt`, могут показать в SecureMesh кнопку установки. Отмена системного диалога оставляет доступными ручные инструкции. В отдельном окне установленного приложения эти инструкции скрыты. [Механизм установки Chromium](https://web.dev/learn/pwa/installation-prompt/)

Чтобы проверить готовый пакет на Linux, выполните `python3 tests/pwa/install_desktop.py /tmp/securemesh-pwa` с Playwright и его полной сборкой Chromium. Временный профиль устанавливает пакет через DevTools, выбирает режим отдельного окна, открывает хранилище и справку офлайн, затем удаляет приложение. Флаг `--headed` запускает проверку с видимым окном. Системный диалог на устройствах Apple и Android проверяется отдельно.

## Черновики переписок

Браузер сохраняет текст отдельно для каждого диалога внутри зашифрованного локального профиля. После паузы во вводе в 350 мс приложение начинает запись. Кнопка блокировки сразу скрывает текст и запускает сохранение оставшихся изменений. При аварийном завершении браузера до окончания записи последний ввод может потеряться. Отправка удаляет соответствующую редакцию черновика вместе с постановкой сообщения в очередь. Текст, введённый во время отправки, остаётся в редакторе. Черновики доступны только в этом профиле браузера и исключены из экспортируемой истории.

## Проверка на стенде

1. В Safari на iPhone откройте `https://pwa.test.example.org/app/` и добавьте страницу на экран «Домой». Откройте значок при подключении к интернету. Перейдите в справку по ссылке SecureMesh в шапке мессенджера и дождитесь отметки «Справка доступна офлайн».
2. В лаборатории профиля проверьте создание и открытие тестового профиля. Проверьте web–native обмен на паре отдельного браузерного и нативного устройства. Сверьте ключи до обмена.
3. Отключите сеть, закройте приложение и откройте его с экрана «Домой». Проверьте запуск справки и открытие локального профиля. Для отправки и получения сообщений восстановите сеть.
4. Сверьте в инструментах браузера список кешированных путей с пакетом. Убедитесь, что вызовы API проходят только к указанному узлу и что запрос с постороннего origin не получает разрешающий CORS‑заголовок.

Артефакт предназначен для испытания. Публичный выпуск требует проверки на физическом iPhone, независимой проверки безопасности и прохождения приёмки на целевом сервере.

### Блокировка приглашений в подтверждённом чате

Откройте «Анкета собеседника», разверните «Настройки приглашений» и выберите «Заблокировать приглашения». Сервер отменяет ожидающие входящие приглашения от этого аккаунта и запрещает новые. Для обеих сторон скрываются фото профиля, описание и статус. Принятые приглашения и доставка сообщений в существующих чатах сохраняются. В той же анкете можно выбрать «Разблокировать».

При открытии анкеты PWA сверяет блокировку с сервером. Если подтверждение изменения потерялось, кнопка «Повторить проверку» загружает текущее состояние перед следующим действием. Состояние блокировки и поля анкеты собеседника в локальном профиле не сохраняются. Вкладка очищает поля при блокировке, закрытии окна анкеты или смене чата.

Для разблокировки разрешён cross-origin `DELETE` на `/v1/contact-blocks/{username}` с настроенного HTTPS-источника PWA. Интеграция с локальным API и PostgreSQL проверяется командой `python3 tests/pwa/contact_blocks_browser.py`.

### Блокировка доставки в существующем чате

В подтверждённом личном чате откройте «Анкета собеседника», затем «Блокировка сообщений в этом чате». Эта настройка действует для выбранного чата. Она отличается от блокировки входящих приглашений, которая по-прежнему управляет приглашениями и видимостью анкеты.

Пока хотя бы один участник сохраняет блокировку, сервер отклоняет новые MLS-конверты в обе стороны. Уже принятые сервером сообщения и вложения остаются доступны, даже если получатель увидит их только при следующей синхронизации. Сервер не расходует номера сообщений и не меняет эпоху MLS при таком отказе. Клиент может сохранить отклонённое сообщение в очереди и доставить его после снятия обеих блокировок. Настройка управляет доставкой через сервер в выбранном чате. Она не удаляет полученные копии и не завершает уже активные прямые звонки.

Локальная проверка использует `tests/integration/conversation_message_blocks.py` для HTTPS, WSS и гонки записи в PostgreSQL. Сценарий двух аккаунтов в Chromium находится в `tests/pwa/message_blocks_browser.py`.

База данных поддерживает блокировку и при временном возврате к прежней версии API. Прежняя версия возвращает общую ошибку сохранения, а повтор уже принятого конверта получает прежний номер. Полное восстановление PostgreSQL переносит принятые сообщения и активные блокировки. Для проверки смешанных версий передайте `--pre-block /путь/к/SecureMesh.Api.dll` в интеграционный тест.

Отзыв доступа к устройству действует и во время блокировки. Снятие блокировки не удаляет отозванное устройство из состава MLS. Сервер по-прежнему отклоняет новые сообщения с ошибкой `MLS_ROSTER_REKEY_REQUIRED`, пока устройство не исключено поддерживаемой процедурой смены состава. Если исключение этого устройства невозможно, для продолжения нужен новый подтверждённый чат.

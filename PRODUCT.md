# SecureMesh

<!-- impeccable:product-schema 1 -->

## Platform

adaptive

## Stack

User brief pins Flutter stable, Material 3, Rust/OpenMLS, .NET and PostgreSQL. Routine visual choices are delegated explicitly; no preference interview is requested or needed.

## Users

People exchanging private text over unstable connections, including simulated GPRS/2G, on Android and Linux desktop. Future iOS/web support is gated on actual crypto/platform tests.

## Product Purpose

Persistent offline queue, authenticated device identities and actual encrypted message delivery, with honest queued/saved/device-delivered states.

## Capabilities and Constraints

Source of truth: immutable 01_TZ_PRODUCT_RU.md through 10_AGENT_EXECUTION_RULES_RU.md. Existing tested slice: CLI OpenMLS/SQLCipher and TLS API delivery. Native application is in development. No fake data, decrypted private server history, public deployment or security-audit claims. Explicitly show incomplete local-alpha status. Public and private scopes must remain visible.

## Brand Commitments

Working name SecureMesh. Material 3, original styling, RU/EN, light/dark, keyboard and assistive technology support. No third-party messenger branding.

## Evidence on Hand

Real process tests and command logs in reports/evidence. No user photographs, public posts, call evidence or mobile build evidence supplied.

## Product Principles

1. Local durable persistence precedes network work.
2. Crypto errors block sending and preserve recoverable state.
3. Connection and receipt labels reflect actual state.
4. Device verification is an explicit action.

## Accessibility & Inclusion

Material focus/semantics, scalable text, 48 dp touch targets, RU/EN and system light/dark preferences. Native device screenshots and accessibility testing remain required.

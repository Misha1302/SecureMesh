# SecureMesh — автономная разработка защищённого мессенджера и социальной сети

**Версия ТЗ:** 1.0, 2026-11-18. **Статус:** комплект документов для реализации. **Исходный продукт НЕ создан этим архивом.**

## Что внутри

1. `01_TZ_PRODUCT_RU.md` — полное ТЗ: функции, роли, режимы приватности, медиа и UX.
2. `02_ARCHITECTURE_RU.md` — архитектура, компоненты, хранилища, схемы взаимодействия.
3. `03_2G_RELIABILITY_RU.md` — требования к доставке при GPRS/EDGE, бинарный протокол, offline-first, тесты.
4. `04_SECURITY_E2EE_RU.md` — криптографическая архитектура, угрозы, ключи, восстановление, ограничения.
5. `05_STACK_REPO_RU.md` — проверенный стек, архитектура репозитория, окружения и инструменты.
6. `06_ROADMAP_RU.md` — зависимости этапов, критерии завершения и действия Codex.
7. `07_TESTING_ACCEPTANCE_RU.md` — формальная приёмка; **все P0 обязательны**.
8. `08_DEPLOYMENT_HANDOFF_RU.md` — подготовка к будущему развёртыванию без реального продакшена.
9. `09_API_STORAGE_RU.md` — контракт API, базовая модель данных, состояния сообщений, права доступа.
10. `10_AGENT_EXECUTION_RULES_RU.md` — правила автономного выполнения и отчётности.
11. `docs/DECISIONS_AND_TRADEOFFS_RU.md` — ADR-решения и сравнение альтернатив.
12. `docs/SOURCES_AND_CAVEATS_RU.md` — официальные технические источники и риски SDK.
13. `contracts/wire.proto` — проектная начальная схема бинарного транспорта (не реализация).
14. `checks/ACCEPTANCE_MATRIX.csv` — **неизменяемый шаблон** приёмки; Codex копирует его в `reports/ACCEPTANCE_MATRIX.csv` и записывает туда реальные статусы.
15. `AGENTS.md` — инструкции, которые Codex читает автоматически из корня репозитория.
16. `PROMPT_CODEX_START_RU.txt` — **единственный текст, который нужно скопировать в Codex**.
17. `tools/verify_bundle.py` / `MANIFEST_SHA256.txt` — проверка целостности комплекта.
18. `tools/run_codex_autonomous.sh` — опциональный запуск нескольких ограниченных сессий, `tools/check_completion.py` — предварительный контроль матрицы и тестового gate.
19. `PROMPT_CODEX_RESUME_RU.txt` — продолжение задачи после ограничения одной сессии.

## Самый простой запуск

Создай **пустую отдельную папку проекта**, распакуй в неё этот ZIP, открой Codex с рабочей директорией этой папки и вставь **весь** текст `PROMPT_CODEX_START_RU.txt`. Для CLI после распаковки (если `codex` установлен и авторизован):

```bash
# Выполнять из отдельной папки, куда распакован этот архив:
python3 tools/verify_bundle.py
codex exec --sandbox workspace-write - < PROMPT_CODEX_START_RU.txt
```

Команда `codex exec` запускает **одну неинтерактивную сессию**, а не гарантию завершения многомесячного проекта за один запуск. Для ограниченного числа последовательных автономных сессий можно вместо `codex exec` запустить `MAX_CODEX_RUNS=12 ./tools/run_codex_autonomous.sh` (это может расходовать доступные лимиты и не гарантирует завершения). Если среда оборвётся/исчерпает лимиты, запусти снова с `PROMPT_CODEX_RESUME_RU.txt`; состояние работ хранится в репозитории (`STATUS.md`, `PLAN.md`, `reports/`). **Не использовать `--yolo` / danger-full-access**, не открывать текущий продакшен-репозиторий, не передавать секреты.

Если агенту нужны сетевые пакеты или Docker, их возможности зависят от предоставленных ему разрешений. Он обязан вести честный статус и не выдавать непроверенное за готовое. Отсутствие внешних API-ключей не блокирует локальную демонстрацию: использовать Mailpit, локальный push-adapter и MinIO.

## Что считается результатом

Рабочий монорепозиторий с backend, клиентами, E2EE на поддержанных платформах, публичными пространствами, медиа, локальным запуском, воспроизводимыми тестами, минимально жизнеспособной инфраструктурой, документацией и доказательствами работы в плохой сети. **Не** красивый лендинг, моки вместо доставки или «архитектура на бумаге».

Перед реальными пользователями обязательно отдельное ревью безопасности криптографической интеграции, зависимостей, модели угроз и эксплуатационной конфигурации. Никакая формулировка промпта не заменяет независимый аудит.

## Ключевое ограничение

Разработка и тесты — автономно; публикация/отправка SMS/e-mail реальным людям, регистрация платных ресурсов, изменение реальных серверов, доменов и ключей — **не выполняются**. Финальный этап этого пакета — подготовленный к переносу продукт, dry-run деплоя и конкретная инструкция для владельца.

=== ЦЕЛЬ ПРОДУКТА И КРИТИЧЕСКИЕ ПРИНЦИПЫ ===

Создай социальную сеть уровня базовых возможностей Telegram: аккаунты по username/email, личные и групповые чаты, публичные каналы и сообщества, профиль, поиск публичного, реакции, ответы/редактирование, изображения, GIF, документы, голосовые, видеокружочки, видео, 1:1 WebRTC аудио/видеозвонки, административная панель, модерация, RU/EN, адаптивный красивый интерфейс, мобильные/desktop клиенты и доступный browser surface.

ОДНО ИЗ ГЛАВНЫХ ТРЕБОВАНИЙ — НАДЁЖНЫЙ ТЕКСТ НА 2G. В синтетическом GPRS 20 Кбит/с, RTT 1500 мс, потери 3%, а также в severe 2G 10 Кбит/с, RTT 3000 мс, потери 10%, текст должен не теряться после durable ACK, не дублироваться в UI и в итоге доставляться при функционирующей связи. Секунды не гарантируются при полном обрыве. Медиа на 2G можно остановить или отложить. Должны работать offline outbox (дисковое сохранение), reconnect, WSS + HTTPS fallback, cursor-based sync, persistence через перезапуск клиента/сервера, backpressure и приоритет текста.

В личных чатах и закрытых группах — НАСТОЯЩЕЕ E2EE без доступа админа к plaintext. Шифрование не самописное: RFC 9420 MLS + реальная библиотека OpenMLS/Rust, корректный AS/DS, key packages, эпохи, trust/new-device warnings, key management на клиентах; шифрование медиа до загрузки. 1:1 может быть MLS group, в том числе с отдельными устройствами. Публичные каналы — явно публичный, серверу читаемый контент, допускающий поиск и модерацию. Администратор управляет инфраструктурой, ролями, ограничениями, жалобами, но не получает криптографический бэкдор.

НЕЛЬЗЯ добавлять custom crypto primitives, выдумывать безопасность, заменять E2EE server-side AES или автоматически переключать private chat в plaintext при ошибке. Пароли — Argon2id + уникальные соли, а не шифрование и не SHA256. Аккаунт recover не восстанавливает E2EE history без отдельного защищённого пользовательского ключа/доверенного устройства.

=== ПРЕДПОЧТИТЕЛЬНЫЙ СТЕК ===

Backend: ASP.NET Core/.NET 10 LTS, C#, PostgreSQL, EF Core/Npgsql, modular monolith с clear modules; MinIO/S3 для media; Redis только cache/presence optional; одна атомарная transaction на message + outbox; protobuf over WebSocket + HTTPS sync fallback; Docker Compose локально. Flutter stable для Android/Linux desktop, iOS и других платформ по фактической возможности; Rust OpenMLS через bridge для E2EE; web только после работающего native/WASM crypto compatibility spike (без insecure E2EE fallback). WebRTC + coturn для 1:1. Mailpit для dev email. OpenTelemetry/structured logs с redaction; netem/test namespaces и/или Toxiproxy для плохой сети; CI и lockfiles. Не городи Kubernetes, Kafka и микросервисы без фактической причины.

Если версия/библиотека несовместима, выясни это небольшим проверяемым spike и выбери технически обоснованную поддерживаемую альтернативу с ADR; не провозглашай несовместимость без реального теста.

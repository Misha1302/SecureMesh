# Личные файлы и фото

Участник подтверждённого личного разговора может передать файл размером от одного байта до 4 МиБ. Клиент сохраняет подготовленное вложение в SQLCipher и сначала загружает шифротекст. После успешной загрузки он одной локальной транзакцией создаёт MLS-сообщение в исходящей очереди и освобождает временную копию шифротекста. Получатель выбирает загрузку вручную. Старый клиент видит текст со значком скрепки и именем файла.

Для каждого вложения клиент получает случайный ключ AES-256-GCM, 96-битный nonce и UUID объекта. Криптографические операции выполняет провайдер OpenMLS. Клиент связывает тег с версией формата, идентификаторами разговора, сообщения и объекта, именем, типом и размером исходного файла. Дескриптор с ключом и nonce передаётся внутри MLS. Получатель проверяет длину и тег перед возвратом открытых байтов приложению. При сохранении через системный диалог пользователь создаёт обычную копию файла вне зашифрованной базы.

## Что хранит сервер

Таблица PostgreSQL `private_blobs` содержит идентификаторы разговора, объекта и владельца, шифротекст и его SHA-256. Длина объекта равна размеру исходного файла плюс 16 байт. Сервер также видит время обращения и устройство, выполнившее запрос. В запросах с файлом отсутствуют имя, формат и ключ. Принятый сервером MLS-конверт хранится отдельно, как обычное сообщение. Резервная копия PostgreSQL включает обе таблицы. Для расшифровки после восстановления требуется исходное клиентское хранилище с состоянием MLS или сохранённым дескриптором.

Маршрут `/v1/conversations/{group}/blobs/{id}` принимает бинарный PUT с заголовками `Content-Type: application/octet-stream` и `Content-Length`. GET и PUT требуют доверенного действующего устройства в составе разговора. DELETE дополнительно проверяет владельца. Повторный PUT того же шифротекста возвращает 204. Попытка изменить объект с тем же идентификатором возвращает 409. Превышение квоты возвращает 507.

| Ограничение | Объём | Число объектов |
| --- | --- | --- |
| Подготовленные файлы на устройстве | 64 МиБ шифротекста | 64 |
| Файлы одного аккаунта на сервере | 64 МиБ шифротекста | 1024 |
| Все файлы на сервере | 256 МиБ шифротекста | 8192 |

Один процесс API принимает до четырёх загрузок одновременно. Квоты проверяются в транзакции PostgreSQL и действуют суммарно для всех экземпляров API. Объединённый лимит регулирует полезную нагрузку, а фактический размер БД, WAL и резервных копий зависит от PostgreSQL. Сервер хранит объект до удаления владельцем. Отзыв доступа ограничивает новые запросы и сохраняет уже полученные копии на устройствах.

## Сеть и границы проверки

Приложение отправляет шифротекст блоками по 32 КиБ. Последний блок может быть короче. Перед каждой попыткой клиент читает подтверждённое смещение через GET на подмаршруте `/parts`. PUT на `/parts?offset=N` содержит бинарный блок, размер всего шифротекста в `X-Blob-Length` и его SHA-256 в `X-Blob-SHA256`. Сервер подтверждает зафиксированные байты, принимает идентичный повтор и проверяет хеш целого объекта перед публикацией. Незавершённый объект доступен только для продолжения владельцем. Сервер резервирует квоту сразу на полный размер. Через 24 часа без новых блоков резерв истекает и очищается при следующей записи. Старый бинарный PUT продолжает принимать целый объект.

При скачивании клиент использует HTTP Range и сохраняет принятые блоки в SQLCipher. После перезапуска он запрашивает недостающий суффикс. В SQLCipher хранятся до восьми частичных загрузок, самые старые вытесняются. Через 24 часа неактивности новый запрос может начать загрузку заново. Имя файла и его содержимое не передаются в запросе диапазона. Для экспорта всё вложение проходит проверку AEAD. Мост Dart/Rust по-прежнему передаёт ограниченный объект целиком при подготовке и окончательной расшифровке. На слабой сети автоматическая отправка откладывается, пользователь может запустить её вручную. Успешный PUT и локальная постановка MLS-сообщения в очередь разделены сетью. После сбоя локальный этап позволяет повторить PUT без дубликата.

Тест `tests/integration/private_blobs.py` использует обычный HTTPS API, PostgreSQL, Mailpit и отдельные процессы Rust с независимыми базами SQLCipher. Он обрывает TLS-соединение посередине блока, перезапускает API и проверяет сохранённое смещение. При загрузке получателем проверяется восстановление локального префикса после перезапуска. Он проверяет передачу файла 4 МиБ и PNG, отклонение изменённого тега, доступ участников, квоту, повторную отправку после аварии, выгрузку и восстановление БД и расшифровку исходным получателем. Если установлен Dart SDK, тот же тест запускает два отдельных процесса приложения через библиотеку Rust FFI. Обе передачи продолжаются с сохранённых 32 КиБ, а SHA-256 полученного открытого файла сравнивается с исходным. Он не измеряет время передачи в сетях 2G и не проверяет системные диалоги Flutter на физических устройствах.

## Воспроизведение и границы доказательств

- Linux Flutter 3.50.0: 18 widget-тестов на объединённом коде, включая 320dp, повторную проверку ключа, Unicode-профили, поиск, закрепление/архив, черновики и форматирование. В независимом тесте Rust/SQLCipher — откат незавершённой записи, повтор отправки и изоляция черновиков.
- .NET 10.0.111, PostgreSQL 17.12, Rust 1.93.1, Mailpit 1.27.10. Docker отсутствовал. Сервисы запущены отдельными локальными процессами с TLS. [Подробности 10 прогонов на исходниках направления доставки](../reports/evidence/modernization-live-delivery.json). [11 прогонов объединённого кода, проверки receipt, миграций и обновления](../reports/evidence/modernization-integrated.json). При остановленном API сообщение осталось в очереди после SIGKILL, при возобновлении получатель увидел его один раз.
- [Измерение слабой сети](../reports/evidence/modernization-shaped-link.json) проводилось через Toxiproxy без потерь пакетов. Исторические шесть GPRS/severe прогонов хранятся отдельно и не переаттестуют текущий бинарник.
- В исходной сборке после обновления url оставались четыре записи RustSec. В кандидате на OpenMLS 0.10.0-rc.1 и SQLCipher 4.20.0 осталось одно информационное предупреждение по сопровождению proc-macro-error2. Сканирование кандидата завершилось с нулём известных уязвимостей. Для этого набора зависимостей требуются платформенная приёмка и независимый аудит. [Результаты проверки кандидата](../reports/evidence/rustsec-remediation.json).
- Гайд сайта содержит реальные изображения и отмечает границы alpha. Проверены шесть сочетаний ширины и темы и десять внешних адресов. Публичная версия обновляется после слияния через Pages.
- Остаются вне приёмки: присутствие и набор текста с приватностью, биометрия/passkeys, полная доступность, массовая нагрузка, подтверждённое удаление аккаунта и полное тестирование четырёх ОС. Полный реестр — [рабочая матрица V3](../reports/V3_ACCEPTANCE_MATRIX.csv).

## Как проверить Linux-кандидат

В каталоге загрузки выполните `sha256sum -c SecureMesh-Linux-x64-a45e2ad-candidate.tar.gz.sha256`. Ожидаемый SHA-256 — `087b7fba7731236c9aebb28aea11518efceb5cc25d7dd5abc113e65824edade1`. Распакуйте в отдельный каталог. Из него запустите `./securemesh_client`. Проверены Debian 13 x86-64, GTK 3, X11, Mesa/GLES2 и glibc 2.38+. Для функционального испытания нужен совместимый тестовый HTTPS-сервис. [Протокол двух клиентов и снимки](../reports/evidence/modernization-linux-gui/QA_LINUX_GUI_RU.md).

Воспроизводимая привязка: локальному коммиту сборки a45e2ad соответствует опубликованное дерево [9286a9e](https://github.com/Misha1302/SecureMesh/tree/9286a9e369a6d93f55121f047ef2f0ee01bcaf6e), Git tree 9311dae442e0ae13f80ab052233da19d74e27d67. Серверный срез afa4fc5 соответствует [4540bf3](https://github.com/Misha1302/SecureMesh/tree/4540bf36247a63ec9724a851c6d38c63a8562546), Git tree adf8c6f38bcfab254920e8abb04d876bf64b8a6d.

Исторический проверяющий скрипт замороженного брифа сообщает несовпадение хеша AGENTS.md: основная ветка уже содержит принятое дополнение V3 (d5362d9). Изначальный транспортный бриф сохранён байт-в-байт. Изменённый контракт protobuf находится в contracts/runtime/wire.proto. Исходный register оставляет 24 незакрытых P0/P1, V2 — 18 функциональных сценариев. В новой рабочей V3-матрице незакрытые полные сценарии не повышены до PASS на основании отдельных проверок.

[API в конфигурации Release](../reports/evidence/modernization-release-api.json): прошли пять проверок, включая обмен подтверждениями по WebSocket и восстановление PostgreSQL. В декодированном pg_dump нашли точный MLS-шифротекст и проверили отсутствие маркера синтетического личного сообщения в трёх представлениях. После восстановления получатель расшифровал сообщение. Это проверка конкретной резервной копии.

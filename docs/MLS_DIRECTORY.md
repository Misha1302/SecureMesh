# MLS authentication and initial conversation delivery

The sender creates a chat request by username; only the recipient account can accept it on a trusted device. Publication accepts a signed OpenMLS KeyPackage whose BasicCredential UUID and signature key match that authenticated device. A bounded public-only Rust helper runs OpenMLS validation (suite, signature, credential and current lifetime) with no database/store or inherited server environment. It uses the existing OpenMLS implementation, not a second MLS parser. KeyPackageValidator config points to the built helper binary; the development default is src/crypto_core/target/debug/securemesh-crypto. Missing helper fails closed with 503. At most two validations execute concurrently with a five-second timeout.

Publication is idempotent by standard MLS KeyPackage reference and never renews an old record's lifetime. Server availability expires after one hour; the actual MLS lifetime is also validated at allocation. At most 64 unleased current packages per device. Only the request sender can lease for the accepting device. One invitation gets one package, serialized in PostgreSQL; repeats with the same lease UUID return the same bytes. Different IDs cannot reuse it. Leases expire after ten minutes and are never recycled to another invitation.

The sender must independently compare/pin the recipient key. directory_prepare validates the leased reference and pinned recipient, then creates the group, add/Welcome, signature and immutable bootstrap retry request in one SQLCipher transaction. Abort before COMMIT rolls all of them back. The signed transcript binds group, request, lease, both device IDs, package reference, Welcome digest, protocol domain and initial epoch. POST /v1/conversations/establish commits the exact two members, epoch and recipient Welcome atomically. A lost ACK can be retried with identical bytes even after lease expiry. Changed payload conflicts. The request directory returns an additive `established` flag once this invitation has a committed bootstrap. Clients can hide the completed request while continuing to process the separately routed Welcome.

Only the recipient device receives its Welcome. directory_join checks the sender against an independently confirmed pin, the signature/bindings and exact two-member MLS roster. It commits validated Welcome, group and replay fingerprint in one local transaction. An identical redelivery does not overwrite a progressed ratchet; a different Welcome cannot replace an existing group. The recipient acknowledges only after local persistence. Inbox responses are paged/bounded to 20 items and 64 KiB of Welcome bytes.

POST /v1/conversations (the old local harness bootstrap) is disabled by default. Original low-level delivery tests explicitly opt in with EnableLegacyConversationBootstrap=true; application demo uses the routed workflow. Production startup remains disabled regardless of this development fixture flag.

Executed tests: tests/integration/directory.py and migrations.py, plus real signup/username-request/consent/Welcome/DM GUI tests in tests/gui/native_v2.py. This covers initial one-device-per-account DM establishment, not complete multi-device/group membership, key transparency, block UI, expiry cleanup or an audited production AS. Peer pinning is still an explicit independent comparison. Server metadata and denial-of-service remain visible/possible.

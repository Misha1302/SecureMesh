# Сборка нативных клиентов SecureMesh

Для нативных клиентов нужны Flutter 3.50.0 и Rust 1.94.1. Из корня репозитория проверьте зависимости командой `cd apps/client_flutter && flutter pub get --enforce-lockfile`. Перед распространением протестируйте тот же байтовый артефакт на отдельной машине и запишите его SHA-256. Подпись файла удостоверяет издателя, функциональные проверки выполняются отдельно.

## Linux x86-64

На Linux с GTK 3 установите clang, cmake, ninja, pkg-config, libgtk-3-dev, liblzma-dev, компилятор C++, Rust и Perl для сборки OpenSSL. Из `apps/client_flutter` выполните `flutter build linux --release`. CMake собирает Rust-библиотеку по Cargo.lock и помещает её в каталог `lib` комплекта. Скопируйте целиком `build/linux/x64/release/bundle` и запустите `securemesh_client` из другого рабочего каталога. Для локальной отладки со старым debug-комплектом сохранён `scripts/client.sh`. Проверка должна включать создание и открытие зашифрованного хранилища после перезапуска и обмен с другим клиентом.

## Android

Сохранён существующий идентификатор приложения. Для установки обновления поверх старой установки нужны совместимая история подписи и более высокий versionCode. Старый debug-ключ и изолированный лабораторный ключ могут отличаться от ключа распространения. Перед миграцией подтвердите путь обновления на копии профиля.

1. Установите Android SDK с API 36, Android Build Tools, NDK 28.2.13676358, Flutter и Rust. Добавьте Rust-цели `aarch64-linux-android armv7-linux-androideabi x86_64-linux-android` командой `rustup target add` и установите `cargo install cargo-ndk --locked`.
2. Задайте `ANDROID_HOME` и абсолютный путь `SECUREMESH_SIGNING_STORE`. Из защищённого окружения передайте `SECUREMESH_STORE_PASSWORD`, `SECUREMESH_KEY_ALIAS`, `SECUREMESH_KEY_PASSWORD` и сверенный с издателем `SECUREMESH_SIGNER_SHA256`. Пароли и ключ в репозитории не сохраняются.
3. Запустите `scripts/build-android-release.sh`. Gradle собирает библиотеку для arm64-v8a, armeabi-v7a и x86_64. Скрипт сверяет подпись APK и наличие трёх нативных библиотек для каждой архитектуры, затем выводит хеш. Результат находится в `apps/client_flutter/build/app/outputs/flutter-apk/app-release.apk`.
4. Установите проверенный APK на телефон и выполните сценарии входа, записи в локальную базу, перезапуска и отправки через TLS. Лабораторный сертификат не даёт права заменить уже установленный клиент издателя.

## Windows x64

На Windows x64 со средствами сборки Visual Studio C++, CMake, Perl, Rust/MSVC и Flutter выполните `flutter build windows --release` из `apps/client_flutter`. Копируйте весь каталог `build/windows/x64/runner/Release`. Cargo собирает DLL для x86_64-pc-windows-msvc, CMake включает её рядом с exe. Запуск и установка требуют проверки на Windows. Подпись Authenticode в эту сборочную конфигурацию не входит.

## iOS

Существующий отдельный тег `v0.1.0-ios-alpha.1` содержит проект Xcode и unsigned IPA. Проверка на телефоне требует подписи и подходящего provisioning profile. Эти результаты следует привязывать к точному тегу, отдельно от основной ветки.

## Публикация

Матрица приёмки, двухпользовательский E2E, результаты аудита зависимостей и проверка обновления с реального прошлого клиента обязательны для оценки готовности. Сборочная команда не публикует артефакты и не меняет production.

## Подтверждённый обмен Android ↔ Linux

27 ноября 2026 года PR с исходным коммитом `1b61725200a62bf9ffb6fa3eafd1de4d741a8df6` прошёл проверку передачи текста в обе стороны. CI установил release-mode APK с временной подписью на эмулятор API 35 и проверил запуск. Вторая задача установила тот же APK на API 28, открыла через UI независимую зашифрованную резервную копию тестового профиля и ввела новое сообщение. Нативный клиент Linux использовал рабочие компоненты Dart, Rust, SQLCipher и OpenMLS. Он расшифровал сообщение, отправил ответ и получил квитанцию получателя. Проверка прочитала ответ с экрана Android через Android UI Automator и подтвердила ровно два конверта от двух устройств в службе доставки. Использовались настоящий API SecureMesh, PostgreSQL и проверяемая цепочка TLS с временным корневым сертификатом тестового эмулятора. [Лог обмена](https://github.com/Misha1302/SecureMesh/actions/runs/45965441405/job/140399395158) · [Протестированный APK в архиве Actions](https://github.com/Misha1302/SecureMesh/actions/runs/45965441405/artifacts/15183926467)

Zip-архив Actions для этого APK имеет SHA-256 `6a233f8dcb2e2788aa6a651076b7ddb0a9ef150623aef463d6a0718f4ec572a1`. Подлинность установщика для публичного обновления, установка на физический телефон, первичная регистрация из Android UI, звонки и мультимедиа требуют собственных проверок. Для повторения запустите workflow **Android release-mode verification** и проверьте итог задания `android-linux-interop`. Клиент Linux в этом сценарии запускается как нативный процесс без графического окна.

## Приёмка на физических iPhone, iPad и Android

Для каждого прогона записать модель, версию ОС, тип клиента (нативный, вкладка или установленная PWA), SHA сборки, идентификатор стенда и результат каждого шага. Использовать тестовые аккаунты, тестовую почту и синтетические медиа. Устройство на момент этой приёмки не подключено. Результаты будущего прогона внести в [матрицу платформ](../reports/PLATFORM_MATRIX.csv).

| Сценарий | Действия и критерий |
| --- | --- |
| Приватность в переключателе приложений | В нативном клиенте открыть тестовый чат с различимым текстом и фотографией. Перейти через домашний экран в список недавних приложений и проверить, видна ли переписка. На iPhone и iPad ожидается непрозрачный фон, на Android 13+ — системная карточка без снимка Activity. Вернуться в приложение и проверить обычный экран либо блокировку согласно настройкам. Повторить при просмотре фото, повороте и после биометрического диалога. Старые версии Android, отдельные окна плагинов и PWA проверять отдельно. |
| Установка и обновление | На iPhone и iPad установить PWA из Safari через «На экран Домой», на Android — из Chromium. Запустить в standalone, закрыть, открыть снова, обновить при наличии старой открытой вкладки. Проверить версию, наличие локального профиля и возможность открыть очередь после обновления. Для нативных сборок отдельно проверить подпись и обновление поверх предыдущей версии с сохранением данных. |
| Регистрация и доверие | Получить код в тестовом почтовом ящике, проверить повторную выдачу кода и однократность подтверждения. На втором тестовом устройстве пройти приглашение и согласование полномочий. Смена ключа должна останавливать отправку до проверки по действующей политике. |
| Экран чата | В портретной и альбомной ориентации открыть длинный диалог, показать клавиатуру, переключить чат и вернуться. Проверить safe area, доступность кнопки отправки, позицию прокрутки, сохранность вводимого текста, увеличение системного шрифта и озвучивание элементов VoiceOver/TalkBack. На iPad повторить с разделением экрана. |
| Камера, микрофон, файлы | Разрешить, отозвать и повторно выдать доступ. Записать голос и видео, прервать запись блокировкой и входящим звонком. Проверить отмену и доступность повторной записи. При отправке тестовой фотографии с геометкой проверить политику EXIF на полученном файле. В приватном диалоге проверить, что серверное хранилище содержит шифротекст. |
| Фон и сеть | Включить авиарежим, поставить текст в очередь, заблокировать, выгрузить и заново открыть приложение. После перехода Wi‑Fi ↔ мобильная сеть подтвердить доставку одного экземпляра на устройстве другой платформы. Проверить работу при запрете push и после возврата с уведомления без раскрытия закрытого профиля. |
| Хранилище и восстановление | На одноразовом профиле проверить обработку нехватки места и потерю веб-хранилища. Восстановить разрешённую резервную копию. Вход по email на новом устройстве сам по себе не должен открывать старые сообщения. Проверить отзыв этого устройства и отправку после смены эпохи. |

Для пары Android ↔ iPhone повторить передачу текста, приватного вложения и смену состава в обе стороны. Отдельно зафиксировать ограничения фонового выполнения, измеренную задержку, число дубликатов и возможную необходимость повторного пользовательского действия. Скриншоты и журналы для репозитория подготовить на тестовых данных без секретов.

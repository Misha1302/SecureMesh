# Сборка нативных клиентов SecureMesh

Для нативных клиентов нужны Flutter 3.50.0 и Rust 1.93.1. Из корня репозитория проверьте зависимости командой `cd apps/client_flutter && flutter pub get --enforce-lockfile`. Перед распространением протестируйте тот же байтовый артефакт на отдельной машине и запишите его SHA-256. Подпись файла удостоверяет издателя, функциональные проверки выполняются отдельно.

## Linux x86-64

На Linux с GTK 3 установите clang, cmake, ninja, pkg-config, libgtk-3-dev, liblzma-dev, компилятор C++, Rust и Perl для сборки OpenSSL. Из `apps/client_flutter` выполните `flutter build linux --release`. CMake собирает Rust-библиотеку по Cargo.lock и помещает её в каталог `lib` комплекта. Скопируйте целиком `build/linux/x64/release/bundle` и запустите `securemesh_client` из другого рабочего каталога. Для локальной отладки со старым debug-комплектом сохранён `scripts/client.sh`. Проверка должна включать создание и открытие зашифрованного хранилища после перезапуска и обмен с другим клиентом.

## Android

Сохранён существующий идентификатор приложения. Для установки обновления поверх старой установки нужны совместимая история подписи и более высокий versionCode. Старый debug-ключ и изолированный лабораторный ключ могут отличаться от ключа распространения. Перед миграцией подтвердите путь обновления на копии профиля.

1. Установите Android SDK с API 36, Android Build Tools, NDK 28.2.13676358, Flutter и Rust. Добавьте Rust-цели `aarch64-linux-android armv7-linux-androideabi x86_64-linux-android` командой `rustup target add` и установите `cargo install cargo-ndk --locked`.
2. Задайте `ANDROID_HOME` и абсолютный путь `SECUREMESH_SIGNING_STORE`. Из защищённого окружения передайте `SECUREMESH_STORE_PASSWORD`, `SECUREMESH_KEY_ALIAS`, `SECUREMESH_KEY_PASSWORD` и сверенный с издателем `SECUREMESH_SIGNER_SHA256`. Пароли и ключ в репозитории не сохраняются.
3. Запустите `scripts/build-android-release.sh`. Gradle собирает библиотеку для arm64-v8a, armeabi-v7a и x86_64. Скрипт сверяет подпись APK и наличие трёх нативных библиотек для каждой архитектуры, затем выводит хеш. Результат находится в `apps/client_flutter/build/app/outputs/flutter-apk/app-release.apk`.
4. Установите проверенный APK на телефон и выполните сценарии входа, записи в локальную базу, перезапуска и отправки через TLS. Лабораторный сертификат не даёт права заменить уже установленный клиент издателя.

## iOS

Существующий отдельный тег `v0.1.0-ios-alpha.1` содержит проект Xcode и unsigned IPA. Проверка на телефоне требует подписи и подходящего provisioning profile. Эти результаты следует привязывать к точному тегу, отдельно от основной ветки.

## Публикация

Матрица приёмки, двухпользовательский E2E, результаты аудита зависимостей и проверка обновления с реального прошлого клиента обязательны для оценки готовности. Сборочная команда не публикует артефакты и не меняет production.

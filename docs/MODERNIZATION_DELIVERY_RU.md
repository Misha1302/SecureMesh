# Подтверждение смены эпохи при доставке

Приоритет P0. Владелец — ядро доставки. В текущем клиенте NativeDelivery передаёт любую квитанцию durable в операцию saved. Для MLS-конверта kind=3 операция меняет статус записи, но оставляет локальную эпоху прежней до возврата собственного конверта через sync. Подтверждённое сообщение исчезает из очереди до применения смены эпохи. Если при этом вызвать commit_saved, прежняя реализация считает сохранённый статус достаточным для пропуска слияния.

Требование: в транзакции SQLCipher подтверждать собственный ожидающий коммит MLS и завершать запись outbox вместе. Повтор идентичной квитанции должен безопасно завершаться в том числе после синхронизации и перезапуска, расходящийся порядковый номер — отклоняться. Утрата ответа до локальной фиксации оставляет конверт для повтора. Для существующих хранилищ запись saved с ожидающим тем же ID должна завершать слияние при повторе подтверждения. Форматы API и базы сохраняются.

Приёмка: в тесте с двумя реальными MLS-клиентами зафиксировать аварийный выход до commit транзакции, повтор отправки, два одинаковых подтверждения, отказ при изменении номера, отправку приложения в новой эпохе и расшифрование собеседником до получения собственного эха. Отдельно прогнать гонку двух commit в интеграционном тесте epochs.py.
